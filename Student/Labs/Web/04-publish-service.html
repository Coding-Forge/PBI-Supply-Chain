Lab 4 · Release and operations

Publish safely to Power BI US Government

Move the completed report from Power BI Desktop into the correct sovereign-cloud workspace, configure its Web-source credentials, prove refresh works, and validate the experience as a service consumer.

25–35 minutesPower BI Desktop + ServiceDeliverable: published and refresh-tested report

Know your government cloud

Government tenants do not use the commercial app.powerbi.com portal. Confirm your organization’s cloud before signing in or publishing.

GCChttps://app.powerbigov.us
GCC Highhttps://app.high.powerbigov.us
DoDhttps://app.mil.powerbigov.us
Stop if the cloud is wrong. A commercial-cloud license, workspace, or guest identity does not transfer automatically into a government tenant. Use the URL that corresponds to your organization’s tenant.

Preflight the release

  1. Confirm you have a government Power BI Pro or Premium Per User license. Power BI US Government has no Free license.
  2. Confirm you are an Admin, Member, or Contributor in the instructor-approved destination workspace.
  3. Open the completed report in the current Power BI Desktop release and select Home → Refresh.
  4. Clear all slicers. Confirm the unfiltered checkpoints from Lab 3 still match.
  5. Use a release-ready name such as Coding-Forge Supply Chain. Avoid version suffixes such as “final-v2”.
  6. Confirm the report contains only fictitious workshop data. Do not publish controlled, classified, export-controlled, or operational data as part of this exercise.

Publish from Power BI Desktop

1Refresh and save
2Select Publish
3Choose workspace
4Open in service
  1. In Desktop, verify the signed-in account belongs to the correct government tenant. If your account can access more than one cloud, select the government cloud during sign-in.
  2. Select Home → Publish, or File → Publish → Publish to Power BI.
  3. Search for and select the instructor-approved workspace. Do not use My workspace for a team deliverable.
  4. Select Publish. Wait for the success message, then select the report link.
  5. Confirm the browser opens the expected powerbigov.us host. If it opens app.powerbi.com, stop and notify the instructor.
Expected result: the workspace receives two related items with the same base name: a report and a semantic model. Publishing does not send service-side edits back to the Desktop file.

Validate the service experience

  1. Open the report and visit Financial Health, Procurement Exposure, and Executive Review.
  2. On Executive Review, test the page-navigation buttons. In the service, select them normally; Ctrl is not required.
  3. Set a Branch or Program slicer and confirm cards, charts, and matrices respond as they did in Desktop.
  4. Use Reset to default or clear the filters, then verify the four checkpoints above.
  5. Open the workspace and confirm both the report and semantic model are present and owned by the intended team or publisher.

Configure credentials and prove refresh

This model imports public, fictitious CSV files through the Web connector. A reachable cloud Web source normally does not require an on-premises gateway.

  1. In the workspace, open the semantic model’s Settings.
  2. Expand Data source credentials or Gateway and cloud connections.
  3. For https://raw.githubusercontent.com, choose Edit credentials, set authentication to Anonymous, and use the privacy setting approved by your organization for public training data.
  4. From the semantic model menu, select Refresh now.
  5. Open Refresh history and wait for a Completed result. Open execution details if the refresh returns a warning.
  6. If instructed, configure a modest scheduled refresh and leave refresh-failure notifications enabled. Shared capacity supports up to eight scheduled refreshes per day; this lab does not need that frequency.
Azure Government boundary check: GitHub is a public-cloud source. Your tenant or network policy might block sovereign-cloud egress to raw.githubusercontent.com. Do not bypass policy. Record the failure and use an instructor-approved Azure Government storage location or managed gateway route instead.

Share through governed channels

  1. Use workspace roles or a Power BI app to distribute the report to the intended government-tenant audience.
  2. Grant the minimum role required: Viewer for consumption, and Contributor or higher only for authors.
  3. Test access with a designated viewer account or ask a partner to validate the link.
  4. Confirm viewers can interact with the report but cannot edit workspace content.
Never use Publish to web. Publish to web creates unauthenticated public internet access and is inappropriate for government or organizational content, even when a workshop dataset is fictitious.

Republish safely

  1. Make future model and report changes in the controlled Desktop/PBIP source, not only in the service.
  2. Before replacing the semantic model, review the impact warning for downstream reports and workspaces.
  3. Renamed or deleted columns and measures can break dependent visuals. Treat semantic-model changes as a release.
  4. After republishing, recheck credentials when new data sources were added and confirm the automatic refresh succeeds.
