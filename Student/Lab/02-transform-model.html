Lab 2 · Data preparation

Transform the data and build the model

Clean by meaning, not appearance. Preserve real negatives and percentages, remove only invalid records, and connect the tables with a predictable star schema.

Order matters: remove rows that do not belong before spending time converting and correcting their values.

1. Budget vs Actuals

Source text"($120,000)" · 6.00% · N/A
Typed result-120000 · 0.06 · null

Keep data rows and remove the duplicate

  1. Filter Program ID with Text Filters → Begins With → PRG-. This safely removes blank and notes rows even if the footer grows.
  2. Select all columns and choose Home → Remove Rows → Remove Duplicates.
  3. Confirm the query now contains 120 rows.

Trim and normalize text

  1. Select Program ID, Program Name, Cost Center, Budget Category, Funding Source, Contract Number, and Status.
  2. Choose Transform → Format → Trim.
  3. Capitalize Each Word for Budget Category and Status.
  4. Replace Sub-Contracts with Subcontracts, Satellite Comm Upgrade with Satellite Communications Upgrade, and Next Gen Radar Systems with Next-Gen Radar Systems.

Convert money without losing negative values

  1. In Actual Amount, Variance, and Variance %, replace N/A with an empty value.
  2. Select Budgeted Amount, Actual Amount, and Variance.
  3. Choose Transform → Data Type → Using Locale.
  4. Use Currency and English (United States). Parentheses must remain negative: ($120,000) becomes -120000.

Convert the percentage correctly

  1. Select Variance % and choose Data Type → Using Locale.
  2. Use Percentage and English (United States).
  3. Verify 6.00% becomes 0.06, displayed as 6% after formatting.
Correction from the old guide: do not remove the percent sign and then convert to Decimal. That produces 6, which Power BI formats as 600%. Also do not strip parentheses without first preserving the negative sign.

Add a reporting period

  1. Select Add Column → Custom Column.
  2. Name it Fiscal Period and use [Fiscal Year] & " " & [Quarter].
  3. This creates sortable labels such as FY2025 Q1 and FY2026 Q2 for the trend chart.

2. Purchase Orders

Deduplicate and trim

  1. Select PO ID, then Home → Remove Rows → Remove Duplicates. Expect 20 rows.
  2. Select every text column and apply Transform → Format → Trim.

Clean amount and date types

  1. In Amount Paid, replace NULL and - with 0.
  2. Select PO Amount, Amount Paid, and Amount Remaining; use Data Type → Using Locale → Currency → English (United States).
  3. Select Order Date and Delivery Date; use Data Type → Using Locale → Date → English (United States).
  4. Check Column Quality. Do not replace date errors with null until you inspect the original value and confirm it is invalid.

Normalize business labels

  1. Capitalize Each Word in PO Status and Priority.
  2. Replace Apex Dynamics Corp. with Apex Dynamics Corp and Centurion Inc. with Centurion Inc.
  3. Replace Satellite Comm Upgrade with Satellite Communications Upgrade.

3. Programs

Protect the dimension key

  1. Trim all four columns.
  2. Set Program ID, Program Name, Branch, and Contract Number to Text.
  3. Confirm Program ID is unique: 5 rows and 5 distinct values.
Modeling rule: use Programs[Program Name] in slicers and axes. The fact-table names were intentionally inconsistent; the dimension is the governed label.

Build the star schema

Programs
dimension · 5 rows
Budget vs Actuals
fact · 120 rows
Purchase Orders
fact · 20 rows
  1. Open Model view.
  2. Relate Programs[Program ID] to Budget vs Actuals[Program ID].
  3. Relate Programs[Program ID] to Purchase Orders[Program ID].
  4. For both relationships use One-to-many (1:*), Single cross-filter direction, and make the relationship active.
  5. Hide Program Name in both fact tables to steer report authors toward the Programs dimension.

Single-direction filters flow from Programs to both facts. This lets one Program slicer filter budget and procurement without ambiguous loops.
